# Opus 4.5 への指示：Devin移行（実装中心）要件定義（Ask）

## これは Opus 4.5 への指示です。

## 目的

Devinへ「実装（開発）中心」で移行するための **要件定義（Ask）** を作成してください。  
推測は禁止。不明点は質問してください。

## 背景（確定情報）

- Devinは **実装（開発）中心**で運用したい
- ただし、**同じところで同種エラーが連続3回**発生したら、Devinは作業を停止し、**Cursor（このスレッドの司令塔）へデバッグ引き継ぎ**を行う

## 運用ルール（確定情報）

### 1) エスカレーション条件

- **連続3回**（誤検知が少ない）
- 「同じところ/同種エラー」の判定は  
  **エラー文の先頭N文字 + スタックトレースの先頭** で行う（判定が安定）

### 2) エスカレーション時に必ず含める情報（引き継ぎmd）

- 再現手順
- 直近の試行ログ（3回分）
- 変更差分（コミット/PR）
- 期待結果/実結果
- 迷子判定（どこで詰まったか）

### 3) 引き継ぎ先

- **Cursor（このスレッドの司令塔）**

### 4) 権限

- Devinに **GitHub push権限：はい**
- Devinに **Railway操作権限：はい**

## Opus 4.5 のアウトプット要件（Ask）

以下を満たす「要件定義（Ask）」を作ってください：

- 目的・背景
- 期待する運用フロー（通常時 / 例外時）
- エスカレーション判定の明確な定義（N文字のNも含めて要確認）
- Devinが出力すべき引き継ぎmdのフォーマット案（中身は要件として。実装案は禁止）
- セキュリティ（シークレット取り扱い）方針の明確化（不明なら質問）
- 非機能要件（再現性、監査性、責任分界など）
- 受け入れ条件
- NG例
- 例外ケース
- 完了条件

## 要確認（Opusが質問して確定すべき項目）

- エラー判定に使う「エラー文先頭N文字」の **N**
- エラー判定に使う「スタックトレース先頭」の **範囲**（例：先頭何行）
- 「同じところ」の定義にファイル名/行番号を含めるか
- Railway操作の範囲（例：環境変数変更、再デプロイ、ログ閲覧、DB操作可否）
- GitHub権限の範囲（直接main push可否、PR必須か）
- シークレットの扱い（Devinに入力させるのか、人間が投入するのか）
