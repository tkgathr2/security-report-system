# Claude For Chrome：Railway本番Postgresで監査ログ（staff_import）をSQLで確定する

これは Claude For Chrome への指示です。

目的：
- 本番環境でスタッフCSVインポートが「実行済みか/未実施か」を、DBの監査ログで**推測なし**に確定する。
- これにより「再インポート要否」がYes/Noで確定し、Devin引き継ぎ時に迷子になりにくくする。

注意（SEC-01）：
- この工程ではシークレット情報（ログイン情報、接続情報）が必要になる可能性があります。自動入力は行いません。SEC-01 で停止します。
- `DATABASE_URL` 等の接続文字列やシークレット値は、コピー/貼り付け/チャット共有しないでください。

前提：
- Railwayの本番環境が稼働している
- RailwayにPostgreSQL（アドオン/サービス）が付与されている

---

## V16.5-0 Railwayへ移動（ログインが必要ならSEC-01で停止）
1) Railwayダッシュボードを開く
2) ログイン画面が出たら **そこで停止**（自動入力しない）
3) ユーザー（高木）が手動でログインする
4) ログイン完了後、作業を再開する

---

## V16.5-1 対象プロジェクトとPostgresを開く
1) `security-report-system` の本番デプロイに紐づくプロジェクトを開く
2) Postgres（Database / PostgreSQL）サービス（またはアドオン）を選ぶ
3) 画面内に「Data」「Query」「SQL」「Console」等のSQL実行UIがあるか確認する

### SQL実行UIが見つからない場合
- その時点で停止し、このチャットに「SQL実行UIが見つからない」ことを報告する（スクリーン上の候補メニュー名も一緒に）

---

## V16.5-2 監査ログ（staff_import / staff_auto_add）を確認
SQL実行UIで次のSQLを実行してください。

```sql
SELECT created_at, admin_email, action, target_type, payload_json
FROM admin_audit_logs
WHERE action IN ('staff_import', 'staff_auto_add')
ORDER BY created_at DESC
LIMIT 20;
```

実行結果から、このチャットに次を報告してください（必要箇所のみでOK、シークレットは貼らない）：
- `staff_import` が存在するか（Yes/No）
- 存在する場合：created_at / admin_email / payload_jsonの要点（file_name, inserted, updated, skipped）
- `staff_auto_add` が存在するか（Yes/No）

---

## V16.5-3 staff_master の件数と当日追加分の確認
次のSQLを順に実行し、結果（数値）をこのチャットに報告してください。

### 総件数
```sql
SELECT COUNT(*) AS total_staff FROM staff_master;
```

### 当日追加件数
```sql
SELECT COUNT(*) AS created_today
FROM staff_master
WHERE created_at::date = CURRENT_DATE;
```

（必要なら）直近10件：
```sql
SELECT display_name_kanji, display_name_kana, created_at, created_by
FROM staff_master
ORDER BY created_at DESC
LIMIT 10;
```
