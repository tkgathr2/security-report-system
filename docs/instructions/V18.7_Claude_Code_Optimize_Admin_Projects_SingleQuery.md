## V0.2 変更（/projects を1クエリ化）

対象：`router.get('/projects', ...)`

方針：
- `projects` と `project_casts` を `LEFT JOIN` し、`casts` は `json_agg` で配列化して返す
- これにより、現状の「projectsクエリ→castsクエリ」の **2往復**を **1往復**にする

実装要点：

1) `start_date && end_date` の分岐（無限スクロール用）で組み立てるSQLを以下の形に置き換える

```sql
SELECT
  p.id,
  p.project_key,
  p.client_name_raw,
  p.work_date,
  p.work_name,
  p.location,
  p.status,
  p.unique_url,
  p.url_expires_at,
  p.created_at,
  c.name as client_name,
  COALESCE(
    json_agg(
      json_build_object('staff_no', pc.staff_no, 'cast_name', pc.cast_name)
      ORDER BY pc.row_index
    ) FILTER (WHERE pc.project_id IS NOT NULL),
    '[]'::json
  ) as casts
FROM projects p
LEFT JOIN clients c ON p.client_id = c.id
LEFT JOIN project_casts pc ON pc.project_id = p.id
WHERE p.work_date >= $1 AND p.work_date <= $2
GROUP BY
  p.id, p.project_key, p.client_name_raw, p.work_date, p.work_name, p.location, p.status,
  p.unique_url, p.url_expires_at, p.created_at, c.name
ORDER BY p.work_date ASC, p.created_at DESC
```

2) `date` の分岐も同様に casts を含める（WHERE p.work_date = $1、ORDER BY p.created_at DESC）

3) `else`（LIMIT 100）も同様に casts を含める（ORDER BY p.work_date DESC, p.created_at DESC LIMIT 100）

4) **既存の castsMap を作る2本目クエリ**（`pool.query(project_casts ...)`）は実行しない
   - ただし、既存の計測ログ撤去はまだ行わない（検証後）

5) レスポンス整形：
   - 既に `casts` がSQLの列として返るので、`projectsWithCasts` は `result.rows` をそのまま返す
   - `casts` が `null` の場合に備えて `casts: row.casts ?? []` だけは付ける（安全）
