# Claude Code：全体遅延（Devinが固まる）原因特定のためのNDJSON計測ログ追加 V17.2

目的：
- 「全体的に遅く、Devin（実装担当）が固まって動けなくなる」原因を、推測ではなく**実測ログ**で確定する。
- 1回の再現操作で、フロント（計算/描画/スクロール）とバック（/api/admin/projectsのDB処理）のどちらが支配的か切り分ける。

前提：
- 本作業は原因特定（Debug）であり、最適化の実装はまだ行わない。
- シークレット/個人情報（メール、氏名等）をログに出さない。
- ログはNDJSON ingest（HTTP）へ送る。セッションIDは無いので付けない。

ログ送信先（固定）：
- `http://127.0.0.1:7253/ingest/f7e4555a-6639-4502-b86d-deba90e7ea4b`

## V0.1 計測ログの追加（フロント：App.tsx）

対象ファイル：
- `frontend/src/App.tsx`

方針：
- 計測点は少数（3〜5）に絞る。
- 毎レンダーではなく「依存が変わった時だけ走る箇所（useMemo）」と「API呼び出し（fetchProjects）」で時間を測る。

### 1) fetchProjects の開始/終了（時間・件数・append種別）

`const fetchProjects = async (...) => {` の冒頭と、`response.json()` 直後に以下のログを追加する。
※ data.projects の中身は出さず、件数のみ。

```ts
// #region agent log
fetch('http://127.0.0.1:7253/ingest/f7e4555a-6639-4502-b86d-deba90e7ea4b',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({runId:'pre-fix',hypothesisId:'A',location:'frontend/src/App.tsx:fetchProjects:enter',message:'fetchProjects enter',data:{append,startDate:startDate||null,endDate:endDate||null,dateRangeStart,dateRangeEnd,projectsLen:projects.length,loadingMore},timestamp:Date.now()})}).catch(()=>{});
// #endregion
```

```ts
// #region agent log
fetch('http://127.0.0.1:7253/ingest/f7e4555a-6639-4502-b86d-deba90e7ea4b',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({runId:'pre-fix',hypothesisId:'A',location:'frontend/src/App.tsx:fetchProjects:after-json',message:'fetchProjects after json',data:{append,receivedProjectsLen:Array.isArray(data?.projects)?data.projects.length:null},timestamp:Date.now()})}).catch(()=>{});
// #endregion
```

さらに、`finally { ... }` の直前（try/catchの最後）に、関数全体の経過時間ログを追加するため、`try {` の直前で `const t0 = performance.now()` を追加し、finallyで差分を送る。

```ts
// #region agent log
const __t0_fetchProjects = performance.now();
// #endregion
```

```ts
// #region agent log
fetch('http://127.0.0.1:7253/ingest/f7e4555a-6639-4502-b86d-deba90e7ea4b',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({runId:'pre-fix',hypothesisId:'A',location:'frontend/src/App.tsx:fetchProjects:exit',message:'fetchProjects exit',data:{append,durationMs:Math.round(performance.now()-__t0_fetchProjects),projectsLenAfter:projects.length,errorShown:!!error},timestamp:Date.now()})}).catch(()=>{});
// #endregion
```

### 2) useMemo の再計算時間（sortedProjects / filteredProjects / projectsByDate）

以下3箇所の `useMemo(() => { ... })` の先頭と末尾で `performance.now()` 差分を取り、durationだけ送る。
- `sortedProjects`
- `filteredProjects`
- `projectsByDate`

追加するログ（各useMemoで同じ形。hypothesisIdはC）：

```ts
// #region agent log
const __t0_memo = performance.now();
// #endregion
```

useMemoの末尾（return直前 or return後に置ける位置）：

```ts
// #region agent log
fetch('http://127.0.0.1:7253/ingest/f7e4555a-6639-4502-b86d-deba90e7ea4b',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({runId:'pre-fix',hypothesisId:'C',location:'frontend/src/App.tsx:useMemo:<NAME>',message:'useMemo recompute timing',data:{name:'<NAME>',durationMs:Math.round(performance.now()-__t0_memo),projectsLen:projects.length,sortedDatesLen:sortedDates?.length??null},timestamp:Date.now()})}).catch(()=>{});
// #endregion
```

`<NAME>` は `sortedProjects` / `filteredProjects` / `projectsByDate` に置換。

注意：
- 変数名の衝突を避けるため、各useMemoで `__t0_memo_sortedProjects` のように名前を変える。

## V0.3 実行（再現）

1. フロントとバックを通常通り起動する（既に起動中なら再起動する）
2. 管理者でログインする
3. 「案件一覧」画面へ遷移する（初回ロードを待つ）
4. 案件一覧を上下にスクロールして、重い/固まる症状が出る操作を30秒だけ行う
5. そのまま停止し、Cursorへ戻る（ログ回収のため）

完了条件：
- 1回の再現で、NDJSONログが複数行出力される（フロントA/C、バックBの少なくとも各1行）
- ログから「どこが遅いか（フロント計算 or API/DB）」を数値で説明できる
