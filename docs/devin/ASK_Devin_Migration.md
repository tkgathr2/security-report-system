# Devin移行 要件定義（Ask）

## 1. 目的

Devinを「実装（開発）中心」で運用し、効率的な開発サイクルを実現する。
ただし、同種エラーが連続発生した場合は速やかにCursor（司令塔）へエスカレーションし、デバッグを引き継ぐ。

---

## 2. 背景

- 現在、Cursor（Claude）が司令塔として開発全体を統括
- Devinに実装タスクを委譲し、開発スピードを向上させたい
- デバッグで詰まった場合は、無駄な試行を防ぐためCursorへ引き継ぐ

---

## 3. 期待する運用フロー

### 3.1 通常時

1. Cursorが実装タスクをDevinに指示（Issue/Slack/直接指示）
2. Devinが実装を行い、PRを作成
3. Cursor/人間がPRをレビュー・マージ
4. Railwayへ自動デプロイ

### 3.2 例外時（エスカレーション発生）

1. Devinが同種エラーを連続3回検知
2. Devinが作業を停止
3. Devinが「引き継ぎmd」を作成し、Cursorへ報告
4. Cursorがデバッグを引き継ぎ、解決後にDevinへ戻す（または完了）

---

## 4. エスカレーション判定の定義

### 4.1 判定条件

**以下のすべてが一致した場合に「同種エラー」とみなす：**

| 項目 | 一致条件 |
|------|----------|
| エラーメッセージ | 先頭 **500文字** が一致 |
| スタックトレース | 先頭 **10行** が一致 |
| 発生箇所 | **ファイル名 + 行番号** が一致 |

### 4.2 エスカレーション閾値

- **連続3回** 同種エラーが発生した場合にエスカレーション

### 4.3 カウントリセット条件

- エラーが解消した場合
- 異なるエラーが発生した場合
- Cursorから明示的にリセット指示があった場合

---

## 5. 引き継ぎmdの要件

### 5.1 必須項目

Devinがエスカレーション時に作成する引き継ぎmdには、以下を必ず含めること：

| 項目 | 内容 |
|------|------|
| タイトル | エラー概要（1行） |
| 再現手順 | エラーを再現するための手順（番号付きリスト） |
| 直近の試行ログ | 連続3回分のエラーログ（省略なし） |
| 変更差分 | 関連するコミットハッシュまたはPR URL |
| 期待結果 | 本来どうなるべきか |
| 実結果 | 実際に何が起きたか |
| 迷子判定 | どこで詰まったか、何を試したか |
| 仮説（任意） | 原因の推測があれば記載 |

### 5.2 ファイル命名規則

```
docs/devin/escalation/YYYY-MM-DD_HHmm_<概要>.md
```

例：`docs/devin/escalation/2026-01-31_1430_OAuth_redirect_error.md`

---

## 6. 権限

### 6.1 GitHub権限

| 操作 | 可否 |
|------|------|
| ブランチ作成 | 可 |
| コミット・プッシュ | 可（feature/fixブランチのみ） |
| PR作成 | 可 |
| **mainへの直接push** | **不可** |
| PRマージ | 不可（Cursor/人間が実施） |

### 6.2 Railway権限

| 操作 | 可否 |
|------|------|
| ログ閲覧 | 可 |
| 再デプロイ | 可 |
| **環境変数変更** | **不可** |
| **DB操作** | **不可** |

---

## 7. セキュリティ（シークレット取り扱い）

### 7.1 基本方針

- **Devinにシークレットを入力させない**
- シークレット（APIキー、DBパスワード等）は人間が事前にRailway/GitHubに設定
- Devinはシークレットの「存在」を前提にコードを書く

### 7.2 シークレットが必要な場合

1. Devinは「シークレットXXXが必要です」とCursorへ報告
2. 人間がRailway/GitHubに設定
3. Devinは設定完了の連絡を受けて作業再開

### 7.3 禁止事項

- シークレットをコード・ログ・コメントに含めること
- シークレットをSlack/Issue等に平文で記載すること

---

## 8. 非機能要件

### 8.1 再現性

- 引き継ぎmdの再現手順に従えば、Cursorが同じエラーを再現できること
- 環境依存（ローカル/本番）がある場合は明記すること

### 8.2 監査性

- すべてのエスカレーションは `docs/devin/escalation/` に記録
- PRには関連するエスカレーションmdへのリンクを含める

### 8.3 責任分界

| 責任範囲 | 担当 |
|----------|------|
| 実装・PR作成 | Devin |
| コードレビュー・マージ判断 | Cursor / 人間 |
| デバッグ（エスカレーション後） | Cursor |
| シークレット管理 | 人間 |
| 本番障害対応 | 人間 / Cursor |

---

## 9. 受け入れ条件

以下をすべて満たすこと：

- [ ] Devinが実装タスクを受けてPRを作成できる
- [ ] 同種エラー連続3回でDevinが自動停止する
- [ ] エスカレーション時に引き継ぎmdが作成される
- [ ] 引き継ぎmdに必須項目がすべて含まれている
- [ ] mainへの直接pushがブロックされている
- [ ] シークレットがDevinのログ・出力に含まれない

---

## 10. NG例

### NG例1: エスカレーションせずに試行し続ける

```
❌ 同じエラーを10回試行してから報告
✅ 3回目で停止し、引き継ぎmdを作成
```

### NG例2: 引き継ぎmd不足

```
❌ 「エラーが出ました」だけの報告
✅ 再現手順・ログ・差分・期待/実結果を含む詳細な報告
```

### NG例3: 権限逸脱

```
❌ mainに直接push
❌ Railway環境変数を変更
❌ シークレットをコードに含める
✅ PRを作成してレビュー依頼
```

---

## 11. 例外ケース

### 11.1 緊急hotfix

- 本番障害など緊急時は、人間の判断でmain直接pushを許可する場合がある
- その場合も事後にPR/Issueで記録を残す

### 11.2 エラー判定が困難な場合

- エラーメッセージが動的（タイムスタンプ等）で判定困難な場合
- → Devinは「判定困難」としてエスカレーションし、Cursorが判断

### 11.3 外部サービス起因のエラー

- 外部API障害など、コード修正で解決できないエラー
- → Devinは状況を報告し、人間/Cursorの判断を仰ぐ

---

## 12. 完了条件

以下をすべて満たした時点で、Devin移行の要件定義は完了とする：

1. 本ドキュメントがCursor/人間に承認される
2. Devinに本ドキュメントの内容が共有される
3. テストタスクで運用フロー（通常時・例外時）が検証される
4. 受け入れ条件がすべてチェックされる
